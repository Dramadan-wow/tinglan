# 听澜 5.4：双电脑共享服务器与连接码

本版保留 5.3 的业务和 UI。登录页新增「服务器连接设置」，提供本地、局域网、云服务器三种模式。远程模式强制 TLS，不能跳过证书验证。云模式是连接已有后端的入口，不会自动购买或部署云服务器。

## 数据与配置

- 原始 `%LOCALAPPDATA%\Hsx Coursework\听澜\client.json`、`server.json` 不覆盖。
- GUI 保存到同目录 `connection-active.json`；常规新版启动优先读取它。`--client-config 文件` 优先级最高。
- 原始本机开发模式仍使用 127.0.0.1 和原有数据库。选择「本地模式」即可恢复默认启动选择。
- 新局域网 `server.json` 的 `workspaceFile`、`usersFile` 解析自 A 的原始配置，使用原绝对路径；不设置 `workspaceImport`，不拷贝测试数据库覆盖真实数据。
- 平台账号、密码哈希、好友、群组、消息、动态图片、微博私信、会员与审核记录由 A 的 SQLite 中心库保存。窗口缓存和主题等设备偏好仍可在各电脑本地保存，不代表独立业务数据库。
- B 原来的本地账号不会自动合并进 A；应使用 A 已有账号，或连接 A 后注册。会员在 A 上审核，不会自动按本机缓存授予。

## 1. 部署当天在 A 生成配置

先接入你信任的目标 Wi-Fi，用 `ipconfig` 查看 A 在该网络的 IPv4。程序**不自动使用当前 Wi-Fi 地址**。建议在路由器为 A 保留地址。

双击项目根目录 `配置局域网.cmd`，输入部署当天的 A 地址。它调用 `scripts/prepare_lan.py`，需要 Python 3 和 cryptography（当前开发电脑已具备）。B 不需要 Python、Qt SDK 或开发工具。

也可在项目根目录 PowerShell 中运行：

```powershell
.\scripts\configure_lan.ps1 -ServerAddress '在这里填A地址'
# 如连接域名，则额外指定实际监听的网卡地址：
.\scripts\configure_lan.ps1 -ServerAddress '你的实际域名' -ListenAddress 'A的实际IPv4'
# 仅有明确需要时才监听所有 IPv4 网卡，防火墙仍须限定受信任接口：
.\scripts\configure_lan.ps1 -ServerAddress 'A的实际IPv4' -ListenAddress '0.0.0.0'
```

每次创建新 `lan-profiles\时间戳\`，不会覆盖旧配置：

```text
lan-profiles/时间戳/
  backup/                 一致性 SQLite 备份和原始配置；仅 A 保存
  server/server.json      TLS、56110、idleExitMs=0、原中心库绝对路径
  server/ca.key           CA 私钥，仅 A 保存
  server/server.key       服务端私钥，仅 A 保存
  server/ca.pem, server.pem
  certificate-info.json   SAN、有效期、CA SHA256
  Start-Server.cmd        独立服务端启动窗口
  Start-Server.ps1
  client/                 仅公共连接配置与 CA，无程序
  connection-code.txt   将里面的文字发给 B，并发送通用 Client-Setup.exe 安装包
```

生成前用 SQLite backup API 备份已提交的 WAL 数据并做完整性检查。缺少原中心数据库时拒绝继续。旧 TCP 的 `users.json` 若从未创建则记录缺失；正常平台账号仍在 SQLite 中，绝不因此新建空的中心库。

CA 有效期 365 天、服务端证书 90 天；SAN 只包含你输入的连接 IP 或域名。换 IP 后须重新生成并更新两边配置和 CA，不能只改 host。域名需实际解析到 A。CA 不导入系统信任库。私钥及备份目录限制为当前用户和 SYSTEM 访问。

## 2. A 启动独立服务器

1. 关闭 A 上所有旧听澜客户端，等待原本机服务器空闲退出（约 60 秒）。
2. 检查 `Get-NetTCPConnection -State Listen -LocalPort 56110`。若仍占用，先核对进程命令行；不要结束不认识的进程、不要删除数据库锁文件。
3. 双击生成目录里的 `Start-Server.cmd`。必须看到 `listening address=... port=56110 tls=true` 或对应 TLS 启动日志。失败窗口会保留错误信息；端口占用和数据库占用不会偷偷换库。
4. 保留该服务端控制台窗口。它与客户端窗口无父子生命周期绑定，`idleExitMs=0`，关闭所有客户端仍会运行。停止时在该窗口按 **Ctrl+C**。它不是 Windows 服务，关机/注销后需重新启动。
5. A 双击生成目录 `Start-Owner-Client.cmd`，使用中心库原有昵称和密码登录。

等价启动命令：

```powershell
& '.\build-package\v5.4.0\runtime\im_server.exe' --config '.\lan-profiles\生成的目录\server\server.json'
```

必须从完整运行时目录使用服务端；不要单独拷出 EXE 而漏掉 Qt DLL、TLS 插件或 SQLite 插件。

## 3. 仅放行受信任局域网

A、B 使用同一可信 Wi-Fi，确认没有访客/AP 隔离。Windows 当前网络仅在你确实信任该网络时通过系统设置改为「专用」。校园/公共 Wi-Fi 不应仅为测试而标记可信，建议使用自己的路由器或热点。

在 A 管理员 PowerShell、项目根目录预览，再应用：

```powershell
.\scripts\lan_firewall.ps1 -LocalAddress 'A的实际IPv4' -FriendAddress 'B的实际IPv4' -InterfaceAlias '实际Wi-Fi接口名'
.\scripts\lan_firewall.ps1 -LocalAddress 'A的实际IPv4' -FriendAddress 'B的实际IPv4' -InterfaceAlias '实际Wi-Fi接口名' -Apply
```

只允许专用网络、指定网卡、A 的指定地址、B 的单个地址访问 TCP 56110。没有 UDP 放行、路由器端口映射、数据库端口或公用网络规则。本次未自动修改 Windows 网络类别或防火墙。若曾手动允许过听澜访问所有公用/专用网络，请在 Windows 防火墙高级安全中检查并禁用那些更宽泛的旧规则；精确规则不会抵消旧的宽泛放行。

撤销规则（管理员 PowerShell）：`Remove-NetFirewallRule -Name 'Tinglan-Trusted-LAN-56110'`。

## 4. B 连接

将 **Tinglan-5.4.0-Client-Setup.exe** 发给 B，双击安装。将生成目录 **connection-code.txt** 的完整文字发给 B，在连接设置中粘贴，自动识别并保存。无需 ZIP，公共 CA 随文字导入；安装包不包含管理员界面、服务器、私钥或数据库。

粘贴连接码后使用部署时填写的地址，端口 56110，并强制 TLS、关闭本机启动。界面显示的是证书 DER 的 SHA-256 指纹，与 `certificate-info.json` 的 `caSHA256` 核对；不是 PEM 文件哈希 `caFileSHA256`。首次保存前确认连接码来自 A。

也可在新版登录页点击「服务器连接设置」：

1. 选「局域网模式」。
2. 填 A 的地址及 56110。
3. 选择 A 提供的 `ca.pem`。
4. 点击「保存并返回登录」，再登录或注册。保存时不声称服务器已经连通；实际登录会执行 TLS 验证。

朋友专用包禁用本地模式，因为其中没有服务器程序。普通完整发行包支持三个模式。命令行 `--client-config` 可明确指定配置。朋友正常启动会读取 GUI 保存的选择；更换服务器时发送新的文字连接码即可，不需要重发安装包。更改 IP 必须同时签发匹配 SAN 的服务端证书。

云模式同样强制 TLS；公共 CA 签发的证书可留空 CA 字段。不要照抄示意图中的域名，必须使用你实际部署且证书 SAN 匹配的服务地址。

## 5. 两台实体电脑验收

1. B 执行 `Test-NetConnection -ComputerName 'A的实际IPv4' -Port 56110`；True 只证明 TCP 可达，还需实际 TLS 登录。
2. A、B 用两个不同账号在同一平台登录。B 新注册后，A 管理员界面应看到新增账号及登录记录。
3. 互加好友，普通会话双向发送中文、emoji、换行和长消息；创建群组邀请对方并群聊。
4. 朋友圈发布图片，对方作为好友可见；未加好友的第三账号应不可见。
5. 开通微博服务并在底部切换，发表图片微博；非好友可见且可从帖子发私信。
6. B 提交会员申请，A 管理员看到同一订单；核验实际付款后审核，B 权益刷新。仅测试流程时不要虚构已付款，不要测试真实支付。
7. B 退出后从另一客户端登录同一个账号（避免同时登录限制），确认好友、历史、帖子和权益仍存在。
8. 关闭 A 的客户端窗口，B 应继续聊天；关闭所有客户端超过 65 秒，A 服务端仍在监听。
9. 断开 B Wi-Fi 再恢复，确认状态和自动重连；停止/重启 A 服务端后双方重新同步历史。
10. A 使用 `Get-NetTCPConnection -LocalPort 56110` 看到两个客户端连接；B 不应出现 im_server.exe 进程或新中心数据库。

实体两电脑、真实 Wi-Fi 路由/AP 隔离和防火墙效果必须在目标网络验收；本机自动测试不能代替这些步骤。

## 6. 恢复本地模式

先关闭局域网客户端，在 A 服务端控制台 Ctrl+C 停止中心服务器，撤销上面的防火墙规则。使用完整版 5.4 的「服务器连接设置」选择「本地模式」并保存，再登录；服务器仍使用原来的 A 数据库，所以局域网阶段写入的业务也保留。旧 5.3 启动入口同样可读取未改变的原始 client.json。

B 恢复本地模式需使用完整版，连接的是 B 原来的本地数据库，不会自动得到 A 数据。不要为了恢复模式还原数据库备份；备份只用于真正的数据损坏恢复，并需先停止服务端及确认目标路径。
