# 听澜 5.6 私聊文件传输

## 使用方式

双方使用 5.6 或更新的客户端，登录同一台启用文件服务的 TLS 中心服务器，并在当前服务中互为好友。选中好友，在输入框左侧点击文件图标，选择文件。文件卡片显示上传进度、速度和预计剩余时间；上传完成且服务端校验通过后，对方收到卡片。对方点“下载”选择保存目录和文件名；校验通过后可点“打开文件夹”。程序不会自动运行 EXE 或其他下载文件。

正在传输时可暂停或取消，暂停后点继续；网络暂时失败会等待并自动重试，连续失败显示“重试”。连接聊天服务器中断时任务保留，重新登录同一服务器、同一账号后继续。主动暂停的任务不会擅自恢复。文件已上传成功后即便发送者退出，对方仍可下载。

上传最终校验阶段不能撤销已发送的文件；取消过程中如服务器已完成发送，会同步为“已上传”。取消下载只删除该任务自己的临时文件。为避免误覆盖，下载时要求选择尚不存在的文件名。上传源文件改变或被删除，需要取消任务并重新选择；服务端已过期的临时任务也需要重新选择文件。

本版本先开放私聊，群聊文件按钮禁用。文件卡片可按文件名搜索，暂不提供文件收藏/撤回、网盘、分享链接、自动病毒扫描。当前列表同步最近 1000 个文件任务；历史文件对象不因此删除。服务端配额为文件存储专用，暂未绑定会员容量，不改变现有会员权益。

## 中心服务器配置

聊天继续使用原有 TCP/TLS 端口（常用 56110），文件新增 **HTTPS 56111**。两个端口复用相同服务端证书，客户端继续按原来的服务器地址、CA 和 SAN 验证，不能关闭验证。文件端口由认证后的登录响应告知客户端，无需每次发文件修改连接码、重打包或在聊天中填写地址。

旧配置默认不启动文件服务，本机明文开发模式保持原样。已有 TLS 部署可运行：

```powershell
python scripts/enable_file_service.py --server-config "实际部署目录/server/server.json"
```

脚本首先用 SQLite backup API 备份现有数据库、保存原配置至配置旁 `file-service-backups/时间戳/`，然后只添加文件服务字段，不修改原用户数据库、地址、证书或账号。不会自动使用当前 Wi-Fi 地址。配置示例：

```json
{
  "fileServiceEnabled": true,
  "filePort": 56111,
  "fileStorageDirectory": "storage",
  "maxFileMiB": 2048,
  "fileQuotaMiB": 20480,
  "fileUserQuotaMiB": 5120,
  "fileMaxConnections": 32,
  "fileTempHours": 168
}
```

这些字段添加到原有 server.json 中，不能用上面的片段替换整个文件。单文件默认 2 GiB（配置最高 8 GiB），总配额 20 GiB、每个上传者 5 GiB，最多 4 个未完成上传任务；预留大小也计入配额。默认临时任务 7 天无更新后过期，服务器每分钟清理。完成文件保留，不自动过期；请监控磁盘、定期备份。

更新服务器可执行文件并正常停止旧进程后，电脑 A 运行：

```powershell
.\build-package\v5.6.0\runtime\im_server.exe --config "实际部署目录/server/server.json"
```

项目内也可双击 `启动中心服务器.cmd`（唯一部署配置自动选取；多个配置时要求明确指定）。确认日志出现 `file_https listening port=56111`。使用独立部署配置 `idleExitMs=0`，客户端退出不会停止服务。不要直接替换正在使用的数据库，不要把原用户数据导入成另一套空数据库。

新建部署时 `scripts/prepare_lan.py` 会启用文件服务；部署者填写实际连接地址，以该地址生成证书 SAN。未来 Ubuntu 仍用 `cmake -S server -B build-server` 构建同一服务端，Qt 6.8+ Core/Network/Sql/Gui，SQLite 和文件目录授予服务账号读写权限即可；生产示例位于 `server/config/production.example.json`。Windows 安装版使用 Qt Schannel，Ubuntu 需要 Qt 支持的 TLS 后端。未在当前 Windows 环境实际执行 Ubuntu 编译。

## Windows 防火墙与双机验证

保留原聊天端口规则。仅在自己信任的专用网络，由电脑 A 在管理员 PowerShell 预览和添加文件端口规则：

```powershell
.\scripts\lan_firewall.ps1 -LocalAddress "电脑A的IPv4" -FriendAddress "电脑B的IPv4" -InterfaceAlias "实际网卡名" -Files
.\scripts\lan_firewall.ps1 -LocalAddress "电脑A的IPv4" -FriendAddress "电脑B的IPv4" -InterfaceAlias "实际网卡名" -Files -Apply
```

脚本限定 Private 网络、指定 A 网卡与地址、指定 B 地址、TCP 56111，禁止边缘遍历；不会开放数据库。若自定义了文件端口，应由部署者创建对应的同样受限规则。不要为了通过脚本把不信任的公共 Wi-Fi 标为专用。

1. A 升级中心服务器并启动，A/B 都安装 5.6 普通客户端（A 也可使用完整管理版）。B 的 `autoStartLocalServer=false`；连接码和已有连接设置可沿用。
2. 用两个不同真实账号登录，在同一服务加好友。确认普通文字聊天正常，输入栏文件按钮可用。
3. A 发 1 KB 中文文件名文本、10 MB 文档、100 MB ZIP；B 下载至不同目录。反向再传一次。
4. 上传/下载过程中暂停，再继续；断开 B 网络后恢复，确认继续任务。暂停后退出客户端并重开，确认任务仍在。
5. A 上传完成后退出；B 重新登录后下载。正常停止并重启 A 的中心服务器，验证完成文件与未完成上传进度仍存在。
6. 对比两台电脑文件哈希：`Get-FileHash -Algorithm SHA256 -LiteralPath "文件路径"`，必须一致。传输中继续互发普通聊天，确认响应正常。
7. 用第三个无关账号验证它看不到私人文件。任意猜测 fileId 不授予访问权限。
8. 验证好友、群聊、会员、朋友圈和微博的原有数据与功能仍在。

当前开发环境自动验证了单机上两个独立 Qt 客户端进程通过真实 TLS/HTTPS 的传输。两台实体电脑、实际 Wi-Fi 断网恢复、不同网络速度及路由器隔离策略仍需按上面步骤实测，不能把单机测试当作双机验收。

恢复旧模式：停止服务，恢复备份中的 `server.original.json`，或将 `fileServiceEnabled` 设为 false；用原客户端连接配置启动。保留 `storage` 以便以后继续使用，无需删除文件或还原用户数据库。移除本次防火墙规则时给相同脚本增加 `-Files -Remove`。

## 存储、协议和恢复机制

`fileStorageDirectory` 相对于 server.json 所在目录解析（也支持绝对路径）：

```text
storage/
  files.sqlite        元数据、参与者、服务、SHA-256、确认偏移、分块记录
  objects/<fileId>.bin 完成文件，文件名由服务器随机生成
  temp/<uploadId>.part 未完成上传
```

原中心业务 SQLite 保持不变，文件内容不存入 SQLite。备份时请同时保留业务数据库、文件索引与 objects/temp；停止服务后整体备份最简单。`file-transfers/` 客户端任务缓存保存在客户端数据文件旁，按服务器地址、聊天端口、CA 和用户编号隔离，不保存密码或 bearer token。下载临时文件位于用户选择的目录，形如 `目标名.tinglan-任务ID.part`，校验成功才重命名。

`FileStorageServiceHsx` 在专用线程运行 HTTPS 和 SQLite；校验使用有界线程池，不占聊天线程。`FileTransferManagerHsx` 不依赖 Widgets，可供未来 QML/Android 客户端使用。网络操作异步，每次最多 1 MiB 数据，哈希以 1 MiB 顺序读取，不把完整大文件装入内存。

登录 TCP 消息声明 `fileTransfer:1`。服务端在通过现有密码认证后返回 `files={port,token,user}`；凭据仅本次聊天连接有效，退出、踢下线和服务端重启后失效。旧客户端未声明能力时不接收新增通知。HTTPS 使用 `Authorization: Bearer ...`，拒绝跨源重定向，客户端从不忽略 SSL 错误。

| 接口 | 用途 |
|---|---|
| `POST /v1/uploads` | `clientId` UUID、name、size、sha256、service、recipient；服务端生成 uploadId 和 fileId，同 clientId 幂等 |
| `GET /v1/uploads/{uploadId}` | 上传者查询已确认连续偏移 offset/state |
| `PUT /v1/uploads/{uploadId}` | 1 MiB 原始二进制块（尾块较小），`Upload-Offset` 和 `X-Chunk-SHA256` |
| `POST /v1/uploads/{uploadId}/complete` | 异步校验整个文件，成功后变为 ready 并通过 TCP `file_notice` 通知双方 |
| `DELETE /v1/uploads/{uploadId}` | 上传者取消尚未最终提交的任务 |
| `GET /v1/files` | 当前用户有权查看的任务列表及大小上限 |
| `GET /v1/files/{fileId}` | 只允许文件参与者，支持单段 `Range`、`If-Range`、206/416 |

顺序上传采用连续确认偏移，SQLite 额外记录每个块的偏移、大小和 SHA-256；重试已确认块会校验一致性，不重复写入。网络恢复先查询 offset，只上传未确认部分。服务端重启会将临时文件修剪到确认偏移；最终校验/重命名有恢复状态。SHA-256 不一致不会标记 ready。下载采用分段 Range、临时文件与最后完整校验，损坏的临时文件在用户重试时从头重新下载。

文件名仅作显示元数据，拒绝路径穿越、控制字符和 Windows 保留名；文件路径始终由服务端 UUID 决定。上传检查当前好友关系、服务与双方屏蔽状态，下载按文件发送者/接收者及服务授权检查。允许常见文档、图片、压缩包及其他二进制类型，统一按附件返回；类型标签来自扩展名，不表示已经做病毒扫描。

该实现面向当前单服务器课程项目；未来公开互联网部署应增加运维监控、备份恢复演练、上传滥用限速、恶意文件扫描和历史列表分页。群聊与网盘需要明确群成员/分享授权和会员配额策略后复用这些模块，不能简单放开现有私聊权限。

## 源码与自动测试入口

- `server/FileStorageServiceHsx.*`：HTTPS、磁盘文件与 SQLite。
- `server/ChatServerHsx.*`、`WorkspaceBackendHsx.*`、`main.cpp`：认证绑定、好友授权、通知、文件服务配置和线程生命周期。
- `network/FileTransferManagerHsx.*`、`ChatClientHsx.*`：任务状态、流式上传下载、恢复与协议能力。
- `gui/FileMessageCardHsx.*`、`ChatPageHsx.*`、`AppSessionHsx.*`、`IconHsx.cpp`：文件卡片、按钮与会话集成。
- `scripts/enable_file_service.py`、`prepare_lan.py`、`lan_firewall.ps1`：部署与备份。
- `tests/file_service_integration.py`：1 KB / 10 MB / 100 MB、权限、重启、Range、异常块、取消、聊天响应。
- `tests/file_client_integration.py` 和 `file_client_probe.cpp`：两个真实 Qt 进程、暂停恢复、进程重启、离线下载、失败重试、卡片截图。

本机编译后分别运行两个 Python 测试脚本；结果写入被 Git 忽略的 `tests/file-output/`，所有账号、数据库、证书、文件均为隔离测试数据。Linux 构建与实际双机测试需要在对应环境另外执行。
