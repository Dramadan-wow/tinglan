# 听澜 5.0 社交平台改造

本轮在既有 Qt Widgets + Qt TCP/TLS + SQLite 平台上实现，没有删除原聊天界面、课程功能或真实存档。旧的公开广场迁为好友朋友圈；新增独立公开微博。运行入口和用户说明见「听澜5使用说明.md」。

## 服务端与协议

沿用已有长度前缀 JSON 包和 `workspace_command/workspace_result/workspace_sync`。所有操作的 actor 来自已认证连接，客户端不能自行指定操作者；请求 UUID 沿用数据库中的操作去重和事务提交。服务端校验可见范围后才生成发送给各用户的快照，朋友圈图片不会被下发给非好友。

|操作|参数与行为|
|---|---|
|feed.publish|channel 为 moments 或 weibo；text 最多 2000 UTF-8 字节；可带 image（JPEG base64）|
|feed.like/comment/delete|先验证 post 对当前用户可见，再更新；删除限作者|
|weibo.follow|target、enabled；关注与好友关系独立|
|weibo.block|target、enabled；阻止双方新私信并隐藏彼此动态|
|weibo.dm.send|target、text、post；首次从对方公开帖子发起，此后可回复；对方未回复前 24 小时最多 3 条|
|weibo.dm.read|target；仅标记自己的收件记录|
|membership.order|tier、reference；价格由服务器决定，最多一笔待核验订单|
|membership.cancel|id；仅允许取消自己的待核验订单|

快照增加 `weibo`、`follows`、`socialBlocks`、`directMessages`、`membership`、`membershipOrders`；`feed` 改为当前用户有权限看到的朋友圈。私信只发给参与的双方，订单只发给本人。旧客户端未传 channel 时默认朋友圈。

`SocialStoreHsx::migrate` 为 posts 增加 channel、image，另建 follows、social_blocks、direct_messages、memberships、membership_orders 表和必要唯一索引。升级前在库旁以 SQLite VACUUM INTO 创建备份，原动态内容保留。图片存入 SQLite，校验 base64、大小、解码尺寸并重新编码；不保存客户端本地图片路径。

`SocialStoreHsx::review` 仅供持有服务器文件访问权限的维护者，在停止服务后从 CLI 调用；不存在客户端自助批准接口。同一真实交易单号不能核销两次，批准和权益更新在同一事务完成。支付仍为人工核验，没有支付接口。

## 修复在线会员报错的原因

之前装扮页使用 `AppSessionHsx::mutate`，在线模式会拒绝修改本机课程业务数据，因而连主题等个人偏好也报错。现在外观设置使用 `personalize`；订单提交和取消调用服务端 command；在线会员读取服务器快照，既能正常保存外观，也不会通过本机修改绕过服务器订单核验。

## 构建与发行

当前已用 Qt 6.8.3 / MSVC x64 编译。服务端新增 Qt Gui 仅用于 QImageReader 的图片验证，不使用 Widgets，不创建图形窗口。Ubuntu 需要匹配版本的 Qt Core、Network、Sql、Gui 及 SQLite/JPEG/TLS 插件；本轮没有 Linux 实机编译记录。

```powershell
# 在项目目录，使用项目自带 CMake
& .tools/python/cmake/data/bin/cmake.exe --preset qt-desktop "-DIM_DESKTOP_OUTPUT=$PWD/build-gui/app"
& .tools/python/cmake/data/bin/cmake.exe --build --preset qt-release --parallel 4 -- /nodeReuse:false
python scripts/package_windows.py
```

打包脚本要求已有本机 MSVC、Qt SDK、Inno Setup 6.7.3（.tools/packaging/InnoSetup/ISCC.exe）。只包含指定的程序、Qt 插件、MSVC 运行库与许可证，不读取 bin/data 或 server/data。便携启动器通过 Windows 自带 .NET ZIP 类解压，避免依赖被执行策略限制的 PowerShell Archive 脚本模块；中文路径已经实际验证。

## 后续边界

当前按用户发送完整快照，图片随快照传输；最新 20 条动态、10 条评论和 200 条私信是显示窗口，尚无分页与对象存储，不适合大量媒体或高并发。头像、背景、装扮选择仍保存在各设备本机；会员权益与订单由服务器统一。

下一步先做带游标的增量消息/动态分页与独立图片上传接口，再完成公网 TLS、实际 Linux 构建和两台电脑验证。商业充值还需支付平台签名回调、订单对账、独立管理授权与审计；本机服务由设备所有者控制，不能作为正式付费系统的可信权益来源。
