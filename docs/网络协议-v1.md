# 听澜 JSON/TCP 协议 v1

## 传输和边界

所有整数长度头为 **4 字节无符号大端整数**，表示后续 JSON 的 UTF-8 字节数，不含长度头。长度必须在 1–65536 范围。每条 JSON 必须是对象；不接受数组、无效 UTF-8、解析失败、缺失信封字段。客户端和服务端均增量缓存，支持长度头和正文拆分、多个完整帧连发。错误帧返回 error 后关闭连接。

除显式允许的数字回环地址测试外，TCP 外层使用 TLS 1.2+。不同平台必须使用相同协议；原 CLI 点对点的纯文本帧协议不兼容。

## 通用信封

```json
{
  "v": 1,
  "type": "chat",
  "id": "03252f91-eef5-44f1-8fd6-aa35dff74631",
  "senderId": "alice",
  "recipientId": "bob",
  "data": {"text": "你好，听澜🙂"}
}
```

v 必须为数字 1。id 为小写、带连字符的 UUID；客户端生成请求 ID，服务器生成响应 ID。senderId/recipientId 必须为字符串，不使用的字段传空字符串。账号格式 `[a-z][a-z0-9_]{2,31}`，当前它既是登录名也是不可变的用户标识。data 必须为对象。字段名称大小写敏感。

## 消息类型

| 类型 | 方向 | data 字段与行为 |
|---|---|---|
| login | 客户端→服务器 | username、password；senderId 和 recipientId 为空。认证通过后将账号绑定到该连接 |
| login_result | 服务器→客户端 | requestId、ok、userId、code。requestId 对应 login.id |
| chat | 双向 | text。客户端发送时 recipientId 指向对方；服务器转发时根据连接身份重建 senderId，保留 id，并增加 serverTime |
| message_ack | 服务器→客户端 | messageId、ok、code、duplicate。messageId 对应 chat.id |
| heartbeat | 双向 | 已认证客户端带自己的 senderId；服务器回复 data.requestId 对应请求 ID |
| error | 服务器→客户端 | code、requestId；帧不能解析时 requestId 可为空 |

login 密码需要 12–128 UTF-8 字节。认证使用服务端随机盐 PBKDF2-HMAC-SHA256 600000 次迭代，不通过网络交换本地凭据文件。错误用户名和错误密码返回相同 invalid_credentials，计算均在线程池执行。一次只允许一个登录请求在该连接上计算；成功后不能切换绑定身份。

chat 正文不能全为空白，UTF-8 最多 16384 字节，整个序列化 JSON 仍不得超过 65536 字节。聊天内容作为纯文本展示。服务端只接受与已认证用户相同的 senderId，自行填写其他账号会收到 sender_mismatch。未经认证发送 chat 会收到 not_authenticated。

转发时间 serverTime 为服务端生成的 UTC ISO 8601 字符串，不作为消息唯一标识。客户端未来不得通过提交服务端时间字段改变服务端判定。

## 确认、去重和失败语义

message_ack 的 ok=true、code=forwarded 表示**已加入接收方连接的发送队列**。这不保证接收方应用已经处理、显示或持久化，也不是已读回执。

服务端以 `(认证用户, chat.id)` 去重，并比较收件人和正文的摘要。同一 ID 同一内容再次提交，会回复 ok=true、duplicate=true，不再次转发；内容变化返回 id_conflict。去重在当前服务进程内保留 10 分钟，最多 10000 条；容量满返回 dedup_capacity。离线、非法消息等失败没有记为已转发，可以随后用相同 ID 重试。服务器重启会清空去重状态。

客户端对收到的 `(senderId,id)` 在当前连接会话的重连过程中也进行 10 分钟去重；主动开始新登录清空此窗口。客户端发送队列最多 100 条待确认消息，等待 15 秒无确认会显示状态未知，不自动重发。手动发送新 ID 可能造成业务重复；持久化接收回执属于下一阶段。

常见 code：invalid_credentials、already_online、invalid_login、login_state、not_authenticated、sender_mismatch、invalid_chat、recipient_offline、recipient_unavailable、id_conflict、dedup_capacity、unknown_type、rate_limit、login_rate_limit、server_busy、invalid_frame_length、invalid_utf8、invalid_json、invalid_envelope、internal_error。

## 连接生命周期和资源限制

- 默认最多 128 个连接，可配置 1–512；超过上限关闭新连接。
- 每连接每秒最多处理 100 条完整消息。
- 每来源 IP 每分钟最多 20 次登录请求；全局最多 16 个进行中/排队认证任务，4 个认证工作线程。
- 默认登录时间限制 30 秒，已认证连接 60 秒无有效 chat/heartbeat 时断开。
- 客户端每 15 秒心跳，45 秒未收到服务端完整消息则重连；连接/认证阶段 30 秒超时。
- 自动重连间隔 1、2、4、8、16、30 秒，成功登录后重置；主动断开、认证失败、证书失败停止重试。
- 每连接接收缓冲限制约 128 KiB，发送队列限制 512 KiB。非法长度立即拒绝，不按攻击者给出的长度分配内存。
- TLS 校验失败不会忽略错误或回退到明文。未认证连接不能用心跳延长登录期限。

客户端网络模块只依赖 Qt Core/Network，使用异步信号槽，不调用 waitForConnected/waitForReadyRead。移动端可复用它，也可以用其他语言实现本协议。
