# 听澜 5.5 普通客户端自动更新

普通客户端启动 4 秒后检查，之后每 6 小时检查。发现新版本显示更新窗口；点击下载，通过 TLS 下载并校验大小与 SHA-256，再点击“安装并升级”。安装成功自动打开客户端。登录页及主窗口底部均有“软件更新”入口，可以关闭自动检查。检查失败不影响聊天，手动检查可看到错误。

## 第一次启用

5.4 及更早版本没有更新器，需给朋友最后一次发送 `Tinglan-5.5.0-Client-Setup.exe` 覆盖安装。保留原安装位置与账号、连接配置。之后无需重复发送压缩文件或证书。

电脑 A 先关闭旧中心服务器，再使用项目的 `启动中心服务器.cmd` 启动本次打包的 5.5 服务端，继续使用原来的 TLS server.json 与数据库。不要删除数据库，不修改 Wi-Fi 地址。普通客户端更新不停止或升级独立服务端。

在电脑 A 双击 `发布客户端更新.cmd`，将当前版本普通安装包发布到原 server.json 旁边的 `updates` 文件夹。存在唯一局域网配置时自动选择该配置；多个配置时由部署者填写。这个脚本只写更新分发目录，不修改 server.json、证书或数据库。它需要 Python 3.11+；当前开发电脑优先使用已有工具运行时。

Windows PowerShell 指定配置：

```powershell
.\scripts\publish_update.ps1 -ServerConfig 'D:\Tinglan\server\server.json'
```

Windows / Ubuntu 手动发布（Python 3.11+，无需第三方库）：

```text
python scripts/publish_client_update.py --release-directory dist/v5.5.0 --server-config /path/to/server.json
```

服务器配置可选 `"updatesDirectory":"updates"`，相对 server.json 解析；不填写也使用该默认目录。只有 TLS 监听提供更新，沿用聊天连接的主机、端口、CA 与 SAN 验证，不新增防火墙端口。保持已有的受信任网络范围规则。

## 以后发布新版本

1. 修改代码，增加 `VERSION`（如 5.5.1），填写 `packaging/update-notes.txt`，重新构建并测试。
2. 运行 `scripts/package_windows.py`，生成普通客户端安装包和 `client-update.json`。执行相关安装、升级和网络测试。
3. 验证后运行发布脚本。只有电脑 A 需要这一份安装包；服务器运行中即可原子更新清单，不必重启。朋友客户端下次检查会发现新版本。
4. 源码按项目约定同步到私有 GitHub。源码提交和发行安装包是两个步骤；GitHub CI 当前不自动打包/发布。

发布脚本检查哈希、大小、版本、渠道及安装包名称；禁止降级，禁止用不同内容覆盖已发布版本。旧版本安装包保留，不自动清空。发布中断遗留 `.publish.lock` 时，先确认没有发布进程，再人工移走该锁；不会自动抢占发布锁。

## 协议与安全边界

使用现有 4 字节长度前缀 JSON 协议。独立连接发送 `update_check`，数据包含 `edition:client`、`platform`（电脑端 `windows-x64`，手机端 `android`，5.7.3 起）、客户端版本；两个平台分别读取 `client-stable.json` 与 `android-stable.json`，互不提供对方的安装包。返回 `update_info` 和经过约束的 release 元数据。`update_chunk` 请求携带 SHA-256 与严格递增的 offset，响应至多 32768 字节的 Base64 数据。每帧不超过 64 KiB，安装包最多 256 MiB。文件经 QSaveFile 原子提交，不完整或不匹配的下载无法进入安装状态。

此端点在登录前可使用，只提供普通 Windows 客户端安装包，不提供管理版、任意路径、URL、账户数据或配置。更新连接不能转为登录会话。空闲 30 秒或连接 30 分钟后关闭；客户端每秒最多约 45 次分片请求。

客户端只接受严格递增的稳定版本号。TLS 强制验证服务器身份及主机名；不会关闭验证，也不内置 GitHub PAT。SHA-256 用于完整性校验，**不是发行者数字签名**：当前信任已配置的中心服务器及其运维人员，掌控服务器或受信 CA 的人可以发布程序。正式公开运营前应加入独立发行签名、公钥轮换及 Windows Authenticode 签名。目前没有代码签名证书，Windows 可能显示未知发行者提示。

安装操作始终需要用户确认。Inno Setup 等待原进程退出（最多 30 秒），不强制关闭应用、不强制重启 Windows；失败时保留已有数据并显示安装错误。不会自改管理员产品或运行中的服务端文件。普通客户端与管理版使用不同 AppId，普通更新包不包含管理界面或本机服务器。

下载中断可以重新下载，暂不支持断点续传、差分更新、Android/iOS 更新、自动回滚或管理端/服务器自动更新。管理端与服务器仍由部署者维护。缓存保存在听澜用户目录的 `updates` 子目录中；安装完成后可以手动清理已下载安装包，切勿删除同级真实数据。

## 验证方法

在隔离目录启动 TLS 服务端，发布高于测试客户端版本的普通安装包。客户端打开“软件更新”，检查、下载、安装，重新打开后版本应更新；原连接码、登录账号和聊天数据应保持。真实发布只能使用实际更高版本，不应篡改清单伪造版本。

自动化：`tests/update_integration.py` 使用真实 Qt 更新客户端和中心服务器验证 TLS、分片、损坏拒绝、取消、版本比较和发布保护；安装器测试独立验证覆盖升级及进程退出等待。测试使用隔离配置、证书及安装目录，不替换真实用户安装。两台实体电脑、外网和 Ubuntu 实机运行须另行验证。

实现依据：[Qt QSslSocket](https://doc.qt.io/qt-6/qsslsocket.html)、[Inno Setup 参数](https://jrsoftware.org/ishelp/topic_setupcmdline.htm)。
